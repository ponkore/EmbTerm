# ADR 0008: 1 つの端末を、Emacs のウィンドウごとのペインで描く

- 日付: 2026-11-11
- ステータス: 採用（TODO [T-016](../TODO.md) / [T-063](../TODO.md)。記録は [../notes/t063-split-copy.md](../notes/t063-split-copy.md)）

## 背景

Emacs では同じバッファを `C-x 2` / `C-x 3` で複数のウィンドウに出せる。
端末のバッファでもこれができて、**ウィンドウごとに別のスクロール位置**で見られること（片方は最新の出力、
片方はスクロールバックを遡る）を要件にした（T-016）。

ところが端末側には制約がある。

- **端末の大きさ（桁・行）は ConPTY に 1 つしか伝えられない。**
- **libghostty-vt のビューポート（いま画面に出ている範囲）も端末に 1 つしかない。**

複数のフレームに同じ端末を出したときは、きれいに見えなくてよい（要件）。

## 検討した案

| 案 | 評価 |
|---|---|
| A: 1 枚の子 HWND の中を複数のペインに分けて描く | 分割の間のモードライン・境界線を覆ってしまう。隣り合っていない配置（`C-x 3` のあと別の窓を挟むなど）に対応できない |
| **B: Emacs のウィンドウごとに子 HWND を 1 枚ずつ作り、端末の状態を共有する** | Emacs のウィンドウの形にそのまま乗る。UI スレッドと GPU デバイスは端末につき 1 つで済む |

## 決定

**案 B。** 端末 1 つにペイン 0〜N 枚。ペイン = Emacs のウィンドウ 1 つ = 子 HWND 1 枚。

- 端末の状態（`Session`）は共有し、**スクロール位置はペインごとに module が持つ**。
- 描くときは端末のロックの中で「そのペインの位置へビューポートを動かす → そのペインの render state に写す →
  いちばん下へ戻す」とする。**いちばん下を追っているペインは、まとめて 1 枚の `Frame` を見る**
  （余計な負荷をかけない）。
- 端末の大きさは**選んでいるペイン**に合わせて ConPTY に伝える。ほかのペインは自分の大きさで切り取って描く。
- 別のフレームに同じ端末を出したときは、今のフレームのウィンドウにだけ置く。
- 子 HWND は親（フレーム）が消されると一緒に消えるが、**端末と UI スレッドは残り**、次に置くときに作り直す
  （制御用のウィンドウは `HWND_MESSAGE` なので親に巻き込まれない。T-066）。

## 帰結

- `C-x 2` / `C-x 3` で分けた窓を、それぞれ別のスクロール位置で見られる。
- 選んでいないペインは、端末の大きさと違う大きさで切り取って描くので、**右や下が欠けて見える**ことがある。
  要件（複数の窓で同じ端末を見るのは補助的な使い方）として受け入れる。
- スクロール位置と選択は `TrackedRef` / libghostty の選択で持つので、出力が増えても同じ行を指す。
- copy モード（T-017）は「そのペインの」スクロール位置を見てバッファに写し、戻ると元の位置に戻る。
- ペインが増えるほどスワップチェーンが増える。描けるペインが無い間は出力の知らせでも写さない
  （読みのスレッドの「知らせを出した」印を立てたままにして、知らせを止める。T-068）。
