# ADR 0006: eaw は 1 桁で固定し、広いグリフの描き方を選べるようにする

- 日付: 2026-11-11
- ステータス: 採用（TODO [T-012](../TODO.md) / T-013 / T-011。要件 [§5.5](../requirements.md)）

## 背景

EmbTerm を作る動機そのものが**文字幅**にある。claude は `①` `★` `※` などの
East Asian Ambiguous（eaw）を**半角 1 桁**として画面を組む。Emacs の `char-width-table` は
全体で 1 つなので、「端末の中だけ幅 1」が作れず、桁がずれていた。

自分で描くようになった以上、幅は自分で決められる。問題は**どちらに決めるか**と、
**1 桁と数えた文字のグリフが全角だったときにどう描くか**である。

端末の中では 3 者が同じ桁数で数えないと画面が崩れる（T-011）。

1. アプリ（claude・vim・yazi）
2. libghostty-vt（EmbTerm の VT）
3. conhost（ConPTY。コンソール API を使うアプリの行編集など）

## 検討した案

**幅をどう決めるか**

| 案 | 評価 |
|---|---|
| 設定で 1 桁 / 2 桁を切り替える | **libghostty-vt の幅の表は固定で、eaw は幅 1**（T-020 で `①` `★` `※` `─` `○` `…` を実測）。切り替えるには上流に手を入れることになる。ConPTY 側には 1.25 から 2 桁にするフラグ（0x20）があるが、それでも conhost は罫線 `─` を 1 桁のままにするので、libghostty-vt 側にも同じ例外が要る |
| **1 桁で固定する** | claude・conhost・libghostty-vt の 3 者が揃う。設定を持たない |

**グリフが全角のときの描き方**（T-013）

| 案 | 評価 |
|---|---|
| **overlap** | 全角の縦横を保ったまま描き、桁送りは 1 セル（右隣へはみ出して重なる）。WezTerm と同じ見え方 |
| **shrink** | 1 セルに収まるよう縮める（ghostel と同じ） |
| 切る | 字が読めなくなる |
| 半角のグリフを持つフォントに逃がす（HackGen Console NF など） | フォントを選ばせることになる。フォールバックの設定で足りる |

## 決定

- **eaw は 1 桁で固定する。** 2 桁にする設定は持たない。
- 広いグリフの描き方は **overlap（既定）と shrink を切り替えられる**ようにする
  （`embterm-narrow-wide`、`embterm.exe` は `--narrow-wide`）。

## 帰結

- claude の桁ずれが解けた。これが EmbTerm の主目的だった。
- **overlap の既知の見え方**（不具合ではない）: 広いグリフが右隣のセルまで描かれるので、
  `★─` のように同じ色の文字が続くと `─` が `★` の腕に重なって見分けにくい。WezTerm も同じ。
  気になるときは shrink にする。
- 合字はしない（セルごとに描く）。
- Emacs のバッファ側（copy モードで写したテキスト）は Emacs の文字幅で表示されるので、
  端末の画面と見た目が一致しないことがある。これは copy モードの性質として受け入れる。
- Unix（macOS）では「ConPTY が画面を組み直す」ことが無いので、3 者の食い違いは起きない。
