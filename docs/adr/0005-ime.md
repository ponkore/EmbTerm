# ADR 0005: IME の変換ウィンドウは tr-ime の上書きで端末のカーソルに合わせる

- 日付: 2026-11-11（T-010）／ 2026-11-16 に T-137 で補強
- ステータス: 採用（TODO [T-010](../TODO.md) / T-083 / T-127 / T-129 / T-133 / T-137。
  調査は [../research/emacs-ime.md](../research/emacs-ime.md)）

## 背景

キーは Emacs が受ける（[ADR 0004](0004-keys-in-emacs.md)）ので、IME の入力コンテキストは Emacs のものになる。
ところが Emacs は変換ウィンドウの位置を**ポイント（隠れたバッファ）の位置**から決める
（`w32_draw_window_cursor` が caret の画素を控え、`WM_IME_STARTCOMPOSITION` で `ImmSetCompositionWindow`）。
端末のカーソルとは無関係なので、変換中の文字列と候補ウィンドウが見当違いの場所に出る。

W32-IME では**変換中の文字列を描くのは IME 自身**（Emacs は `GCS_COMPSTR` を一度も読まない）で、
その窓はトップレベルのポップアップなので、子 HWND の下には隠れない。つまり**位置さえ合えばよい**。

## 検討した案

| 案 | 前提 | 精度 | 評価 |
|---|---|---|---|
| A-1: ポイントを動かす | 素の Emacs | 端末のセルとずれる | 隠れたバッファの文字の並びと Emacs のフォントで決まる。行の高さを合わせるのが難しい |
| **A-2: tr-ime の位置の上書き** | tr-ime advanced | **画素で正確** | `tr-ime-modadv--set-composition-window` に端末のカーソルの画素を渡す |
| A-3: `WM_IME_CONTROL` で直接 | 素の Emacs | 正確だが**持続しない** | Emacs が次にカーソルを描くとポイントの位置に戻される |
| A-4: module が自分でサブクラス化 | 素の Emacs | 正確 | tr-ime と二重になる。重いので最後の手段 |

## 決定

**A-2。** 端末のカーソルのセル → 子 HWND の中の画素 → フレームのクライアント座標に直して
`tr-ime-modadv--set-composition-window` に渡す（`embterm--update-ime`）。
端末のウィンドウを離れたら STYLE 0 に戻し、isearch の後は入れ直す。tr-ime が無ければ何もしない。

**T-137 で 2 つ足した**（記録は [../notes/t137-ime-position.md](../notes/t137-ime-position.md)）。

- 入れた位置は `WM_IME_STARTCOMPOSITION` が来たときだけ IME に渡る。Emacs はカーソルを描き直すたびに
  自分でこれを投げるが、端末は子 HWND に描くので**Emacs の再表示が起きない**。
  そこで module（`embterm-module-ime-refresh`）から同じメッセージを投げて、その場で反映させる。
- 端末のカーソルはアプリのエコーが返るまで動かないのに、IME は**確定と同じ打鍵で**次の変換を始める。
  確定した文字を送ったら、**送った文字の表示幅ぶん位置を先に進めて**おき、エコーが返ったら捨てる。

## 帰結

- **tr-ime advanced が前提**になる。無い環境では変換ウィンドウが Emacs のポイントの位置に出る
  （`embterm-ime-position` を nil にすれば上書きそのものをやめられる）。
- tr-ime の**再変換と前後参照**は、カレントバッファのポイントの行を IME に渡し、確定後に
  `backward-char` / `delete-char` をカレントバッファで実行する。端末のバッファ（隠れていて read-only）では
  害になるので、フックをバッファローカルに差し替えて**空の文字列を通知する**（T-083）。
- アプリがカーソルを隠していても（`civis`。claude のような TUI）、点滅で消えている間も、
  変換中の文字列と候補ウィンドウはカーソルの桁に出す（T-133）。
- macOS には tr-ime が無く、`ns-working-text` の overlay は子レイヤーの下になる。
  `ns-put-working-text` / `ns-unput-working-text` に advice を掛けて**module が自分で描き**、
  候補ウィンドウの位置は `EmacsView` の `firstRectForCharacterRange:` を差し替えて返す（T-127 / T-129）。
  module が毎フレーム描くので、Windows のような位置の遅れが起きないという副次的な利点がある。
