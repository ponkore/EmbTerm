# #9 `test-emacs split` のクリックの選択が 1 行ずれる

- 日付: 2026-11-16
- **[Issue #9](https://github.com/ponkore/EmbTerm/issues/9) の記録**
- 結論: **コードの退行ではない。** テストが**絶対画素でクリックしていた**ため、
  Emacs のフレームの画素の高さ（＝端末ペインの行数）が変わっただけで別の行を指すようになっていた

---

## 1. 症状

`cargo xtask test-emacs split` の 3 項目が落ちる。

```
NG ダブルクリックで単語 -- ("line362")
NG トリプルクリックで行 -- ("line362")
NG M-w で選択がコピーされた -- ("line362")
```

`down:30:24` のダブル / トリプルクリックが `line363` ではなく `line362` を取る。
**選択そのものは効いている**（1 行ずれているだけ）。

## 2. 原因

### 2.1 当時のコミットでも、いま走らせると同じように落ちる

テストが緑だった `d1c95c2`（2026-11-12）を checkout して現環境で走らせると、
**いまの main とまったく同じ 3 項目が同じ値で落ちた**。
`test/split.el` のクリックの座標と期待値は 2026-11-12 以降**一度も変わっていない**
（`down:30:24` と `line363`）。**退行ではない。**

### 2.2 画素 → セルの変換は正しい

このときのセルは **8x18 px、余白 4 px、DPI 96**（`target/t063/module.log`）。
`Renderer::cell_at` は `(y - padding) / cell_h` なので:

| y | 行 |
|---|---|
| 24 | `(24-4)/18 = 1` |
| 42 | `(42-4)/18 = 2` |

遡った上のペインの中身は `line361`（行 0）・`line362`（行 1）・`line363`（行 2）…。
**つまり y=24 が line362 を取るのは正しい。**
実験としてクリックの y だけを 24 → 42 に変えると、**NG 0 で全項目通った**。

### 2.3 ずれていたのは「ペインの行数」

上のペインはいま **15 行**。ホイールで遡る量は 3 回 × 3 ノッチ × `WHEEL_LINES`(3) = **27 行**で不変。
遡った後の上端は `総行数 - ペインの行数 - 27` なので:

| ペインの行数 | 上端 | 行 1 |
|---|---|---|
| 15 行（いま） | `line361` | line362 |
| 14 行（テストを書いたとき） | `line362` | **line363** |

ペインの行数は `(Emacs のウィンドウの画素の高さ - 余白×2) / セルの高さ`。
`emacs -Q` のフレームを 120x40 にしたときの画素の高さは **Emacs 自身の既定フォントの行の高さ**で
決まるので、そこが変われば端末の行数が 1 行変わる。15 行なら本文はおよそ 278 px、
14 行なら 260 px で、**ちょうど 18 px（1 セル分）の差**。

**セルの高さ（フォント・DPI）とペインの行数（Emacs のフレームの画素の高さ）の両方に依存する
絶対画素を、テストが決め打ちしていたのが原因。**

## 3. 直し方

`test/split.el` のマウスの座標を、**そのときのセルの大きさと余白から計算する**ようにした。
期待値も、クリックした行のテキストをペインから引いて使う。

```elisp
(defun split-cell (&optional buf)      ; (幅 高さ 余白) を embterm-module-debug-info から
(defun split-point (col row &optional cell)  ; セルの中央の画素 (X . Y)
(defun split-clicks (point n)          ; point を n 回クリックする指定
(defun split-rows (text)               ; ペインの行（空行も残す。行を数えるため）
```

- ダブル / トリプルクリックと `M-w`: `split-click-row`（= 2、上から 3 行目）の中央をクリックし、
  期待値は `(nth 2 (split-rows (split-pane-text top)))`。
  **クリックする行が `line<数字>` であること**も確かめる（空行をクリックして素通りしないように）
- ドラッグの選択（2 行目 → 3 行目）、Shift+ドラッグ、自動スクロールの押し始めも同じ計算に揃えた
- `test/split.el` に決め打ちの画素は**残っていない**

**`y` を 42 に直すだけにはしない。** それだとテストを書いた環境では逆に落ちるものに変わるだけで、
環境が変わればまた同じことが起きる。

## 4. 確認

`cargo xtask test-emacs split` が **46 項目 OK**（確認を 1 つ足したので 45 → 46）。
ログに計算の過程が出る。

```
セル（幅 高さ 余白）: (8 18 4) / 2 行目 "line363" を (32 . 49) でクリックする
OK クリックする行が `line<数字>' -- "line363"
OK ダブルクリックで単語 -- ("line363")
OK トリプルクリックで行 -- ("line363")
OK M-w で選択がコピーされた -- ("line363")
```

`x = 4 + 3×8 + 4 = 32`、`y = 4 + 2×18 + 9 = 49`。セルやペインの行数が変わっても、
同じ「上から 3 行目の真ん中」を指し続ける。
