# T-125 段階 1: CoreText + Metal で描き、NSWindow に出す

- 日付: 2026-11-13

- 環境: macOS（Darwin 27.2.0）、Apple M1 Max、ディスプレイの拡大率 2、HackGen Console NF
- 結論: **描けた。** 端末の画面（文字・日本語・eaw・色・装飾・カーソル・選択・絵文字）が Metal で出て、
  NSWindow の中で動く。**最悪の画面（200x50、セルごとに色が違う）で描く仕事は 1 枚 1.0 ms**
  （6.27 ms のうち 5.2 ms は垂直同期の待ち）。ふつうの画面（80x24）は 0.7 ms

## 2. 描き方（Direct2D 版との違い）

| | Windows（Direct2D） | macOS（Metal） |
|---|---|---|
| 文字 | 色・フェイスごとにまとめて `DrawGlyphRun` | **グリフのアトラス**（CoreText で 1 つずつラスタライズ → 1 枚のテクスチャに棚詰め） |
| 背景 | セル 1 つ = 1 画素のビットマップを拡大 | 同じ色が続くセルをまとめた**四角のインスタンス** |
| まとめ方 | 背景・文字・装飾を別々に描く | **背景 → 文字 → 装飾 → カーソルを 1 つのインスタンスの列**に積み、1 回の描画で出す（並べた順が重なりの順） |
| 縮小（T-013 の shrink） | フォントの大きさを変えて描く | **その大きさで焼き直す**（アトラスの鍵に縮小の段を入れる）。拡大縮小でぼけない |
| 色付きの絵文字 | DirectWrite の色フォント | CoreText がそのまま色で描く。シェーダで「マスク」と「色付き」を切り替える（`mode`） |
| フォールバック | DirectWrite のフォールバック | 設定のファミリ → `CTFontCreateForString`（システム） |
| 同期 | 待てるスワップチェーン（T-068） | `nextDrawable`（垂直同期で待つ）。**窓では GPU の終わりを待たない** |

**シェーダ**（`gpu.rs` の中に文字列で持ち、実行時にコンパイル）は四角 1 枚のインスタンス描画だけ。
頂点は `vertex_id` から作り、インスタンスごとに「位置・色・アトラスの uv・mode」を渡す。

**踏んだ落とし穴**: MSL の `uint3` は 16 バイト境界なので、Rust の `#[repr(C)]`（`[u32; 3]` は 4 バイト境界）と
構造体の大きさが食い違う（80 対 64）。最初これで**文字がばらばらの位置に出た**。`uint` 3 つに分けて揃えた。

## 3. 測ったこと

`embterm`（release）で、色付きの画面を繰り返し出しながら 1 枚あたりの時間を測った（`--exit-after` のログ）。

| 画面 | 四角の数 | 1 枚 平均 | 最大 | うち垂直同期の待ち（平均） | **描く仕事** |
|---|---|---|---|---|---|
| 200x50、セルごとに色が違う（T-054 の最悪の画面に当たる） | 19,608 | 6.27 ms | 8.30 ms | 5.23 ms | **約 1.0 ms** |
| 80x24、ふつうの出力 | 177 | 1.12 ms | 2.58 ms | 0.44 ms | **約 0.7 ms** |

- 窓は 2616x1366 画素（拡大率 2）。Windows の実測（T-054: 最悪の画面 314x70 で 6〜8 ms）と同じかそれより速い
- **`nextDrawable` は垂直同期まで待つ**（drawable が空くまで）。単体の exe では自分のループなので害は無いが、
  **module（T-126）では描画を Lisp のスレッドから外す**こと（元々そういう設計。requirements.md §6.1）
- 画面の保存（`--screenshot`）はオフスクリーンにもう一度描いて読み戻すので、その回だけ 100 ms ほどかかる（PNG の書き出し込み）

## 4. 目で確かめたこと

`target/t125/` に PNG を出して確かめた（`--screenshot`。拡大率 2）。

| 見たもの | 結果 |
|---|---|
| `hello sh` / プロンプト / タブ位置 | 桁が揃う |
| `日本語`（全角） | 2 セルで正しく表示 |
| `①★※`（eaw。幅 1） | **overlap**（既定）では右隣に重なる、**`--narrow-wide shrink`** では 1 セルに縮む（T-013 のとおり） |
| 罫線 `┌──┬──┐ │ab│cd│ └──┴──┘` | つながった箱になる（20pt で確認） |
| ブロック `█▓▒░` | 正しい濃さで出る |
| 絵文字 😀 | **色付きで出る**（システムのフォールバック + `mode = 2`） |
| SGR（赤・太字の緑・下線・true color・反転） | すべて正しい。太字は別のフェイスになる |
| カーソル | ブロック（フォーカスあり）はセルを塗って文字を反転 |
| 256 色を敷き詰めた画面 | 色がセルごとに正しく出る |

## 5. 自動確認

- **`cargo test -p et-render`**: オフスクリーンに描いて**画素を読み戻して確かめる**試験を 4 本足した
  （セルの寸法と桁数の往復、背景と文字の色、カーソルの塗り、`shrink` で右隣にはみ出さないこと）
- **`cargo xtask test-screens`**: 段階 0 で作った 6 ケースがそのまま通る。macOS では `--headless` を付けて動かし、
  画面のテキスト（期待値との比較）に加えて **PNG も書く**ので、崩れたときに目で見られる
- `cargo check --workspace --target x86_64-pc-windows-gnu`: Windows 側はエラー 0（共通化の refactor を含めて壊していない）
