# T-136 macOS で claude のホイールが入力履歴の切り替えになる

- 日付: 2026-11-15
- 発端: 利用者の報告「[T-135](t135-macos-scrollback.md) で `M-x zsh` は直ったが、`M-x claude` では
  ホイールを動かすとスクロールバックではなく**プロンプトの入力履歴**が切り替わる。
  WezTerm で `claude -r` してホイールを動かすとスクロールする」
- 結論: **マウスを見るアプリに、ホイールを「上下の矢印」として送っていた。** 正しくは
  **マウスの報告として送る**（アプリが自分でスクロールする）。矢印にしてよいのは
  「代替画面 + マウスの報告なし + DEC 1007」のときだけ

---

## 1. claude の TUI が何を立てているか（実測）

PTY で `claude` を起こして、出てきたバイト列の DECSET を並べた
（`python3` の `pty.fork`。プロジェクトのディレクトリで 20 秒）。

| 起こし方 | 立てたモード |
|---|---|
| `claude`（`/tmp`。プロジェクトでない） | `25h` `2004h` `2031h` `1004h` |
| **`claude`（プロジェクトの中）** | `25h` `2004h` `2031h` `1004h` **`1049h` `1000h` `1002h` `1003h` `1006h`** |
| `claude -r` | 同上 |

つまり claude の TUI は**代替画面（1049）に入り、マウスの報告（1000 / 1002 / 1003）と
SGR の符号化（1006）を有効にする**。WezTerm でホイールが効くのは、WezTerm が
**マウスの報告としてホイールを送り、claude が自分の表示をスクロールしている**から。

（プロジェクトでないディレクトリでは立てないので、`/tmp` で試すと再現しない）

## 2. 原因

macOS の `scroll`（`term_mac.rs`）は、マウスの報告が有効なら**矢印キー**を送っていた。

```rust
if mouse {
    let seq: &[u8] = if n > 0 { b"\x1b[A" } else { b"\x1b[B" };   // ← claude には「履歴を遡る」キー
```

claude の TUI では上下の矢印が**入力履歴の切り替え**なので、ホイールを回すと履歴が変わる。

Windows（`term.rs`）は 3 つに分けていて、こちらが正しい（Ghostty と同じ）。

| 条件 | 送るもの |
|---|---|
| マウスの報告が有効（Shift なし）で、ペインがいちばん下を追っている | **マウスの報告**（ホイールのボタン 4 / 5） |
| 代替画面 + 報告なし + DEC 1007（alternate scroll。既定で有効） | 矢印キー（`WHEEL_LINES` 行ぶん） |
| それ以外 | 端末のスクロールバックを動かす |

## 3. 直し方

- macOS の `ScrollAmount::Wheel` を上の 3 分岐にした。報告は `MouseEncoder`（クリックや
  ドラッグと同じ道具）で作る。**Lisp から来るホイールには位置が無いので、ペインの真ん中に
  来たものとして扱う**（Windows と同じ）
- 矢印は `KeyEncoder` で作る（生の `\x1b[A` を書くと、アプリが DECCKM を立てているとき
  `\x1bOA` にならない）
- **Shift を足したホイールは、アプリに見せず端末のスクロールバックを動かす**（端末の慣習）。
  Emacs から来るホイールには修飾キーが乗らない（`embterm-module-scroll` は種類と回数だけ）ので、
  **Lisp 側で `wheel` ではなく `lines` に振り替える**（`embterm-wheel`。Windows でも同じに効く）

## 4. 確かめ方（`test/scrollback-mac.el`、`test/mouse-child.py`）

`test/mouse-child.py` は、受け取ったバイト列をそのまま画面に出す子プロセス。
`mouse` でマウスの報告（1000 + 1006）を立て、`alt` で代替画面に入る。

| 送ったもの | 子プロセスに届いたもの |
|---|---|
| `wheel-up` | `\x1b[<64;43;13M`（SGR のホイール上。43;13 はペインの真ん中） |
| `wheel-down` | `\x1b[<65;43;13M` |
| **`S-wheel-up`** | **何も届かない**（端末のスクロールバックが動く） |
| 代替画面で `wheel-up` | `\x1b[A\x1b[A\x1b[A`（3 行 = `WHEEL_LINES`） |

`mouse_tracking()` が真になるモードも `crates/vt` の単体テストに足した
（1000 / 1002 / 1003 だけ。1006 / 1004 / 2004 / 1049 では真にならない）。
